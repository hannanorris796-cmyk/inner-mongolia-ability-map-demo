## 1. 项目目标与资料依据

本项目先做一套能浏览、能点击、能走通主要流程的桌面端静态 Demo，帮助评估参考产品的业务逻辑、模块关系和使用路径。页面做到结构清楚、信息完整即可，视觉按常规教育行业管理后台处理。

参考资料为用户提供的「内蒙古专业群能力图谱平台」文件夹，包含 340 张 JPG 截图，以及《页面与功能清单.csv》中的 40 项页面或功能。截图数量包含滚动截屏、弹窗、标签切换与节点展开状态，不能直接等同于页面数量。本 PRD 已读取完整清单，并抽查导航、总览、岗位库与溯源、专业群门户、各类图谱、培养方案新建、课程标准编制、供需匹配、需求填报、报告与模板配置等代表截图；未逐张核验全部截图细节。

本文按以下口径区分信息来源：

- **参考产品事实**：功能清单或已查看截图可直接支持的菜单、页面结构和操作入口。
- **产品逻辑推断**：根据模块之间的数据关系推断其用途，不能据此认定原系统已实现自动联动。
- **Demo 设计约定**：为串通演示新增的示例数据、交互、状态、关联跳转与简化计算规则。

资料中的页面文字、提示词、模板配置和操作说明仅作为产品分析素材。它们不构成本次任务的执行指令。

## 2. 产品定位与业务主线

平台面向职业院校，围绕区域产业和企业岗位需求，帮助学校解释「专业为什么这样建、课程为什么这样设、培养出来的人能否满足岗位需求」。

从模块关系推断，产品有三段主要业务：

| 业务阶段 | 用户要解决的问题 | 对应模块 | 主要输出 |
| --- | --- | --- | --- |
| 看需求 | 区域有哪些产业、企业和岗位，需要什么能力 | 产业岗位调研 | 岗位画像、能力要求、需求趋势 |
| 建培养体系 | 哪些专业和课程支撑这些岗位能力 | 专业群能力图谱、培养方案与课程大纲 | 能力映射、培养方案、课程标准 |
| 看差距与形成材料 | 人才供给与企业需求差在哪，如何形成建设依据 | 供需匹配、调研报告 | 差距清单、修订建议、调研报告 |

演示主线：

```text
选择区域与产业链
    ↓
查看产业环节、企业、岗位
    ↓
查看岗位群、任务与能力要求
    ↓
定位支撑专业与课程，识别能力缺口
    ↓
形成培养方案与课程标准
    ↓
对照企业需求查看供需差距
    ↓
形成调研报告和后续修订建议
```

该顺序是推荐的讲解路径。参考产品的多个模块也可独立进入，不要求用户按固定顺序操作。

## 3. 使用者与本次演示身份

| 角色 | 关注点 | 典型操作 |
| --- | --- | --- |
| 学校管理者、专业群负责人 | 专业群布局、产业适配程度、建设依据 | 总览、专业群门户、供需看板、报告 |

## 4. Demo 范围与交互深度

完整保留清单中 40 项功能的入口与对应内容。按页面形态归并为：27 个主页面（含登录）、12 个详情或工作台、1 套公共导航。弹窗和表单步骤可复用页面，不按截图数量逐张制作。

| 深度 | 覆盖内容 | 要求 |
| --- | --- | --- |
| A：完整演示 | 岗位溯源、图谱与课程关联、培养方案、课程标准、企业需求、供需看板、报告新建编辑 | 操作前后有明确状态变化，能跨页继续操作 |
| B：轻量演示 | 趋势预测、新兴岗位、复杂配置、图谱嵌入、动态审议等辅助功能 | 展示主要字段与结果，至少有一项可操作交互 |

A、B 都属于本次 Demo 范围，区别在操作深度。实施时先串通 A，再补齐 B。

所有数据来自前端预设。AI 生成、预测、解析、审核均通过固定结果和短暂进度状态模拟，结果旁标注「演示数据」或「模拟生成」。本次验收范围为浏览器端交互、预设图表、本地保存和文件下载；真实采集、模型调用、后端服务、用户权限系统和服务端文档解析不在该范围内。

## 7. 关键业务对象及图谱含义

### 7.1 对象关系

| 对象 | 核心字段 | 关联对象 |
| --- | --- | --- |
| 区域 | 省份、盟市 | 企业、岗位、需求、供给范围 |
| 产业链与环节 | 名称、上中下游、环节介绍 | 企业、产业、岗位 |
| 企业 | 名称、地区、经营范围 | 招聘记录、需求记录 |
| 岗位群/标准岗位 | 名称、类别、说明 | 招聘记录、任务、能力模块、专业 |
| 招聘记录 | 企业、标准岗位、薪资、学历、经验、来源日期 | 岗位溯源 |
| 能力模块/能力要求 | 名称、要求描述、重要度、依据 | 岗位、任务、技能、课程 |
| 技能点/知识群 | 名称、内容 | 能力要求、课程 |
| 专业群/专业 | 名称、专业代码、培养目标 | 岗位群、课程、培养方案 |
| 课程 | 名称、性质、学分、学时、开课学期 | 专业、能力要求、任务、课程标准 |
| 培养方案 | 名称、专业、年级、来源资料、状态、版本 | 课程体系、能力映射、知识库 |
| 企业需求 | 企业、岗位、人数、优先级、能力权重、状态 | 供需看板、差距分析 |
| 报告/模板 | 名称、范围、章节、参数、状态 | 产业、岗位、课程、引用资料 |

招聘记录中的岗位名称与标准岗位分开：多个企业的招聘记录可归属于同一标准岗位。岗位群是多个标准岗位的集合。专业与岗位群、课程与能力之间均允许多对多关联。

### 7.2 各图谱的侧重点

| 页面 | 关系链 | 用户能看明白什么 |
| --- | --- | --- |
| 七层能力图谱 | 产业链→产业→岗位→能力模块→能力要求→课程→专业 | 区域产业如何连接到学校的专业和课程 |
| 四维映射 | 岗位群→岗位→能力模块→能力要求 | 一个岗位具体要求哪些能力 |
| 知识技能映射 | 岗位群→岗位→任务→能力要求→技能点→知识群→课程 | 岗位任务如何落到教学内容 |
| 课程-岗位关联 | 课程↔岗位，单元格展示支撑能力 | 哪门课程支撑哪些岗位，哪里缺支撑 |
| 能力导向网络 | 专业→岗位→任务→课程→能力项 | 从专业培养出发查看课程支撑网络 |

参考页面把知识技能映射称为「六级链路图谱」，但截图图例及说明实际列出上述七类对象。Demo 沿用菜单名「知识技能映射」，按实际关系展示，不强化存在歧义的层数标签。

图谱采用固定布局和小规模关系数据，选中节点高亮关联路径；双向引用同一组对象，避免不同页面出现同名不同义的岗位或课程。

## 8. 演示数据与跨页一致性

### 8.1 默认业务场景

参考产品截图学校为「内蒙古建筑职业技术大学」，专业群为「供热通风与空调工程技术专业群」，包含供热通风与空调工程技术、建筑智能化工程技术、建筑消防技术、给排水工程技术、电气自动化技术五个专业。Demo 可沿用这些名称用于理解参考场景，界面明确标注演示环境。

Demo 设计约定：默认区域为内蒙古自治区，默认展示「城市生命线智慧运行」相关产业场景；以「电气自动化技术→电气设备运维工程师→配电设备巡检→故障诊断能力→电气控制与PLC应用」为贯通示例。该示例用于串联流程，不代表参考产品已经建立完全相同的映射。

建议初始数据量：5 个专业、3 个岗位群、12 个标准岗位、6 家虚构企业、24 条招聘记录、12 门课程、18 条能力要求、8 项典型任务、6 份知识库资料、3 个培养方案、2 套报告模板、3 份报告。至少一套方案带两个可对比版本，至少两门课程包含能力支撑缺口。

| --- | --- | --- |

### 8.3 供需口径

人数与能力分别展示，避免合成一个含义不清的「匹配度」。

- 人数缺口 = 同区域、同年度、同岗位范围内已通过需求人数 − 预设可供给人数；正值显示短缺，负值显示富余。
- 能力覆盖率 = 已有课程支撑的需求能力权重之和 ÷ 该岗位需求能力总权重。0 权重或无有效能力时显示「暂无可计算数据」。
- 能力权重按岗位归一化为 100%；展示各项权重以及支撑课程。
- 一个学生可能对应多个岗位。供给数据按「演示预分配人数」展示，跨岗位汇总时使用预分配口径，避免重复计数。
- 示例：需求 40 人、预分配供给 28 人，人数短缺 12 人；5 项能力各占 20%，4 项已有课程支撑，覆盖率为 80%。
- 演示预警：人数缺口大于 0 提示缺口；能力覆盖率低于 80% 提示课程支撑不足。这些是 Demo 规则，不作为真实评估标准。

## 9. 核心操作流程

### 9.1 看清产业与岗位需求

进入总览→点击产业入口→选择产业环节→打开关联企业→进入企业详情→点击招聘岗位→进入岗位溯源→查看能力要求→跳四维映射。

必须保留所选岗位；返回企业或岗位列表后保留筛选。企业名称、岗位名称、招聘记录与能力要求引用同一份演示数据。

### 9.2 从岗位能力定位课程

四维映射选择岗位→选择能力要求→点击「查看支撑课程」→打开课程-岗位关联并定位单元格→查看当前覆盖与缺口→打开课程能力推荐→修改提示词或选择课程→模拟生成→勾选推荐项→确认关联。

生成结果先展示为待确认建议；确认后才更新课程映射。已有重复关系不重复新增。点击课程进入课程标准，能看到刚关联的能力项。

### 9.3 形成培养方案

知识库选择资料或上传演示文件→模拟解析完成→培养方案管理点击新制定→选择起点→填写专业、年级、方案名称等→查看生成结果→检查章节匹配→完成创建→预览→保存草稿→版本管理对比。

沿用参考页四步名称「选择起点、填写信息、查看结果、章节匹配」。起点至少提供「从知识库既有方案新建」；模板新建可作为同表单的另一个来源。来源必选；章节匹配至少展示 3 个章节的来源、匹配状态与手动调整。

生成结果展示培养目标、毕业要求、课程结构、学分学时和能力映射等摘要；正文用预设模板填充。更改输入后保留用户输入，返回上一步不清空。

### 9.4 编制课程标准

课程标准列表→点击编制→按章节查看课程信息、性质与定位、目标与内容、考核与评价、实施要求、参考附件→编辑文本、增删表格行→点击 AI 生成预设段落→预览→保存。

原清单描述为六章课程要素；本 Demo 按上述六组归并展示，字段标题在开发时对照截图微调。AI 填充覆盖已有内容前提供「替换本节」和「取消」。课程名称、专业和关联岗位随上下文带入。

### 9.5 看清企业需求与人才缺口

企业需求填报→填写企业、岗位、人数、优先级及能力权重→提交→列表显示待审核→管理员点击模拟通过→供需看板自动带入当前范围→查看人数短缺和能力覆盖→点击预警→跳到对应课程矩阵。

必填企业和岗位；需求人数为正整数；至少一项能力权重大于 0，权重总和为 100%。非法输入在字段下提示，保持已填内容。待审核与已驳回需求均不计入看板；驳回需填写原因，可修改后重新提交。

### 9.6 形成产业链洞察报告

报告列表→新建→选择启用模板→填写报告名称、区域、产业链、专业群、年度→创建草稿→进入编辑器→选择章节→生成本节或全文→检查正文与数据来源→编辑→保存版本→预览→发布。

预设章节为执行摘要、专业群概况、上游分析、中游分析、下游分析、产业链整体分析、结论与专业建设建议。生成内容填入当前范围名称和演示统计；不同章节显示对应的引用资料或对象。使用新模板时读取其目录。

发布显示二次确认；确认后状态变为已发布并可在对应标签查看。已发布报告以预览形式打开，继续编辑时复制为新草稿版本。

### 9.7 查看修订与版本差异

培养方案列表→动态修订→选择已存在版本→模拟审议→查看岗位能力变化、课程支撑不足、建议调整项→选择采纳项→生成修订草稿→版本管理选择新旧版本→展示课程、学时或能力映射差异。

新旧版本分别保留，采纳建议不覆盖旧版本。该状态流为 Demo 约定；参考截图中的审议入口与无版本空状态不足以确认原产品完整审批链。

## 10. 交互、状态与通用规则

| 场景 | 实现要求 |
| --- | --- |
| 所有可见按钮 | 都有可解释的结果：跳转、弹窗、展开、更新、下载或状态提示；禁止只有样式的空按钮 |
| 筛选与搜索 | 在当前页预设数据中真实过滤；支持重置；筛选后重置页码；无匹配结果有空状态 |
| 表格与分页 | 数据多于每页数量时可翻页；总条数与筛选结果一致 |
| 图谱 | 节点可点；至少支持展开、选中高亮、详情；缩放和复位可用；图表切换保持对象一致 |
| 模拟异步 | 0.5–1.5 秒进度反馈后展示固定结果；执行中禁用重复提交；结束后可重试 |
| 弹窗与抽屉 | 有标题、关闭、取消和主操作；取消不改变原数据；表单失败时保留输入 |
| 保存 | 成功提示且数据确实写入本地；离开有未保存修改的编辑页时提示保存或放弃 |
| 本地持久化 | 用浏览器本地存储保留需求、方案、课程、模板和报告的修改；刷新后可恢复 |
| 重置演示 | 管理员菜单提供入口；确认后恢复初始数据，并提示已重置 |
| 下载与导出 | 表格下载 CSV；正文下载 TXT 或 HTML；图谱下载 SVG；按钮明确标注文件类型 |
| 嵌入代码 | 生成本地演示代码并可复制，标注演示链接；不声称支持公共访问 |
| 上传与导入 | 选择本地文件后展示文件名；调用固定解析样例或导入样例；明确说明未解析真实内容 |
| 敏感配置 | 提示词与硬规则只保存为演示配置；不会触发模型或执行脚本 |
| 统计 | 显示范围、年度、单位与演示标识；不同口径不相加；无数据时显示原因 |

主要状态：需求为待审核→已通过/已驳回，驳回后可重新提交；方案为草稿→已完成演示；课程标准为待编制→草稿→已编制；报告为草稿→生成中→待检查→已发布。参考产品未完整展示的状态统一视为 Demo 设计约定。

## 11. 页面呈现与实现约定

以桌面浏览器演示为主，建议 1440×900，最低适配 1280×720。左侧固定导航、白色顶栏、浅灰底、白色内容卡片，蓝色作为主操作色。允许页面纵向滚动，大型图谱和宽表在容器内横向滚动。

列表页优先保证筛选、表格、详情与返回路径；图谱页优先保证节点和关联；工作台优先保证步骤、编辑和保存。图表使用固定数据绘制，不把整张参考截图当作页面主体，保证关键元素可以操作。

建议采用前端单页应用、独立页面路由和共享数据仓库，构建后输出静态文件。岗位、课程、专业、需求、方案、报告统一通过稳定 ID 关联。路由可采用 hash 方式，支持静态服务器直接打开各页面；交付包含启动说明与构建产物。

当前阶段不承诺与参考产品逐像素一致，优先还原布局层级、业务对象、操作入口与结果反馈。
